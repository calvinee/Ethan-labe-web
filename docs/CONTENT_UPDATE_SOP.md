# 时工的半导体实验室：内容更新与自动发布 SOP

版本：V1.1

适用范围：网站与首页、工程文章、Notes 短笔记、工程杂志设置、思维导图、产品项目、系统学习

后台地址：<https://shi-fpga-lab.shi-fpga-lab.workers.dev/admin/>

## 1. 目标

使用可视化后台维护 MDX 内容，避免手工修改网页代码。一次内容保存会形成 GitHub 提交；`main` 分支更新后由 GitHub Actions 构建并发布到 Cloudflare Workers。

## 2. 角色与权限

| 角色 | 负责事项 |
| --- | --- |
| 内容编辑者 | 新建、修改、校对内容；正确使用草稿开关 |
| 技术审核者 | 检查规格、指标、器件范围、公式和工程边界 |
| 发布负责人 | 检查 GitHub Actions 与生产页面，处理回滚 |

只有获得 `calvinee/Ethan-labe-web` 写入权限的 GitHub 账号才能从远程后台保存内容。

## 3. 标准发布流程

### 步骤 1：登录后台

1. 打开后台地址。
2. 点击“使用 GitHub 登录”。
3. 登录后确认左侧能够看到以下六个管理入口：
   - 网站与首页
   - 工程文章
   - Notes 短笔记
   - 思维导图
   - 产品项目
   - 系统学习

### 步骤 2：选择内容库

根据内容目的选择：

| 内容类型 | 选择的内容库 | 前台位置 |
| --- | --- | --- |
| 技术长文、项目复盘、市场分析 | 工程文章 | `/blog/`、首页最新文章 |
| 短判断、调试观察、链接与进行中的想法 | Notes 短笔记 | `/blog/notes/` |
| 系统框架、判断路径、知识梳理 | 思维导图 | `/mindmaps/`、导图详情页 |
| IP 核、PCB、AI 硬件、方案服务 | 产品项目 | `/products/` |
| 课程、阶段路线、学习项目 | 系统学习 | `/learn/` |
| 首页封面、全页场景背景、能力背书 | 网站与首页 | `/` |

### 步骤 3：新建内容

1. 点击“新建”。
2. 填写标题、摘要、日期、标签和正文。
3. 后台默认关闭“草稿”，保存后会直接进入发布流程；如果内容还需审核，请主动开启“草稿”。
4. 点击保存。

草稿会进入 GitHub 内容库，但不会出现在公开页面、站内搜索或 sitemap。

### 步骤 4：内容审核

发布前检查：

- 标题能否直接说明内容价值。
- 摘要是否适合在卡片和搜索结果中独立阅读。
- 型号、速率、资源、延时、价格和交期是否真实。
- 是否说明测试条件、适用范围和已知边界。
- 图片、链接、代码块和表格是否完整。
- 标签是否能命中栏目筛选，例如“IP 核”“AI 硬件”“接口系统”“带宽”。
- “显示顺序”是否与栏目结构一致；数字越小越靠前。

### 步骤 5：正式发布

1. 重新打开已审核内容。
2. 如有必要，将“更新日期”改为正式发布日期。
3. 关闭“草稿”。
4. 点击保存。

保存后 GitHub Actions 会自动构建网站并发布到 Cloudflare。

### 步骤 6：检查自动发布

1. 打开仓库的 Actions 页面。
2. 找到最新的 `Build and deploy Shi FPGA Lab`。
3. 确认构建与发布步骤均为绿色。
4. 如果只显示“构建通过、跳过发布”，检查仓库 Secrets：
   - `CLOUDFLARE_ACCOUNT_ID`
   - `CLOUDFLARE_API_TOKEN`

### 步骤 7：生产验收

至少检查以下位置：

1. 对应栏目列表是否出现新卡片。
2. 点击卡片后，详情页是否正常显示。
3. 使用站内搜索能否找到标题或标签。
4. 草稿内容是否没有被公开。
5. `https://shi-fpga-lab.shi-fpga-lab.workers.dev/sitemap.xml` 是否包含新详情页。

## 4. 各内容库字段规范

### 4.1 产品项目

| 字段 | 填写要求 |
| --- | --- |
| 产品名称 | 使用客户能理解的名称，不只写内部代号 |
| 卡片摘要 | 说明解决什么问题、适合什么场景 |
| 英文眉题 | 例如 `VIDEO IP`、`EDGE AI` |
| 规格摘要 | 只放最关键的接口、性能或交付物 |
| 交付状态 | 现货交付、小批量、预约测试、档期咨询等 |
| 价格说明 | 固定价、起售价、项目制或联系合作 |
| 标签 | 至少包含一个筛选分类：IP 核、PCB、AI 硬件、方案设计 |
| 产品详情 | 写清适用场景、规格、交付物、验证条件和边界 |

涉及价格、库存和交期时，必须在发布前重新确认。

### 4.2 系统学习

| 字段 | 填写要求 |
| --- | --- |
| 课程/阶段名称 | 体现能力目标，而不是只写章节编号 |
| 阶段与周期 | 例如 `STAGE 02 · 3 周` |
| 课时与验收 | 例如 `10 课时 · 2 个验收实验` |
| 学习级别 | 免费、核心、进阶、实战 |
| 标签 | 对应数字基础、RTL 设计、接口系统、工程交付 |
| 详情 | 包含学习目标、核心内容、先修要求和验收产物 |

每个阶段必须有可检查的验收结果，避免只列知识点。

### 4.3 Notes 短笔记

1. Notes 用于短一些的工程判断、调试观察、读书摘记和正在验证的想法，不替代完整技术长文。
2. 标题直接写结论，摘要说明这个判断解决什么问题；正文建议保持 1—5 段。
3. 只有确实需要长期置顶的内容才开启“置顶”，避免所有 Notes 都被置顶。
4. 可选填写配图和相关链接；外部链接必须在发布前检查可访问性。
5. 关闭“草稿”并保存后，内容会进入 `/blog/notes/` 和站内搜索。

### 4.4 思维导图

1. 在后台进入“思维导图”，新建或打开导图。
2. 中心主题建议控制在 6—12 个字。
3. 主分支建议保持 4 个；每个分支填写标题、说明和关键节点。
4. 关闭“草稿”并保存后，导图会进入独立 `/mindmaps/` 索引、搜索和 sitemap；博客主页不再展示大型思维导图专栏。
5. “导图详解”用于解释使用方法、判断顺序和工程边界，不要只重复节点文字。

### 4.5 工程杂志与文章封面

1. 在“网站与首页 → 工程杂志设置”维护杂志简介、Notes 简介、About 文案、联系说明和能力背书。
2. About 文案不展示姓名、具体职位和公司时间线；能力背书保持短句，不使用大型公司 Logo 或论文长标题。
3. 在“工程文章”中可上传“文章封面图”，它会同步显示在博客主页和文章详情页；未上传时自动使用工程图形封面。
4. 封面优先使用 16:10 或 4:3 横图，至少 1200px 宽，并填写准确的“封面图说明”。
5. 博客内容结构为 `Home / Notes / Archive / About`；分类导航会定位到 Archive 中对应主题。

### 4.6 首页封面与背景

1. 在后台进入“网站与首页 → 首页视觉设置”。
2. “首页封面图”控制首页右侧 FPGA 实拍区域；建议使用横图并压缩后上传。
3. “首页背景图”作用于整个首页：图片固定在视口，滚动时保持场景一致；统一阅读遮罩覆盖全页，卡片仍保留实体底色。
4. 背景风格用途：清爽用于长时间阅读，星云用于作品发布，深空用于沉浸展示，电路用于技术内容，极光用于 AI 场景。
5. 背景较复杂时选择“均衡”或“强遮罩”；发布后同时检查桌面和手机端文字对比度。
6. 开启“允许访客切换场景背景”后，访客可在首页右上角切换，并在本机保存偏好。
7. “能力背书”显示在 GitHub 贡献图下方，最多 5 项；只写核心结论，不展示职位、公司时间线、大型 Logo 或论文长标题。

### 4.7 原工程速记归档说明

原“工程速记”已从首页、管理后台、站内搜索、sitemap 和公开详情路由下线，历史文件保留在 `content/notes/` 作为归档。新的 `Notes 短笔记` 是工程杂志中的独立短内容栏目，使用 `content/blog-notes/`，两者不要混用。

## 5. 图片与附件

1. 在编辑器中上传图片，文件会进入 `public/uploads/`。
2. 文件名使用小写英文、数字和短横线，例如 `lvds-eye-scan-20260729.png`。
3. 图片发布前压缩，避免直接上传相机原图。
4. 不上传客户机密、密钥、未脱敏波形或受授权限制的资料。

## 6. 修改与下架

### 普通修改

打开原内容，修改后保存。页面会在自动发布完成后更新。

### 临时下架

1. 打开内容。
2. 开启“草稿”。
3. 保存并等待自动发布。

内容文件仍保留在仓库中，便于后续恢复。

### 永久删除

只有确认内容不再需要且已完成备份时才使用“删除”。优先使用“草稿”下架，避免不可逆删除。

## 7. 故障处理

| 现象 | 处理 |
| --- | --- |
| 后台无法登录 | 检查 GitHub 登录状态和 OAuth Worker 健康状态 |
| 保存后前台没变化 | 检查是否仍为草稿、日期与显示顺序是否正确 |
| Actions 构建失败 | 查看失败文件和 MDX/frontmatter 报错，修正后重新保存 |
| 构建成功但未发布 | 检查 Cloudflare 两个 Actions Secrets |
| 新卡片存在但详情页 404 | 检查文件名、草稿状态和构建是否完成 |
| Notes 保存后未显示 | 检查是否使用“Notes 短笔记”内容库、是否仍为草稿 |
| 内容有严重错误 | 立即开启草稿并保存；必要时恢复 GitHub 上一个正确提交 |
